# SCC data needed to finish the camera fix

The camera's real MCLK is generated by the CRD PMIC (TPS68470), which only
produces it once the Windows **SCC** (System Control Controller) has (a) adopted
the CRD PMIC and (b) enabled the camera rails + Mclk. Everything the SCC owns is
unreachable from Linux (no PCI SCC device, no `/proc/iomem` MMIO, port-EC
`0x66/0x62` has no memory shadow, no MEI client). So the fix is: **extract the
SCC's camera enable sequence + pin map from Windows, then drive the PMIC via the
CRD convention from Linux** (or reproduce the SCC writes if the register block
turns out to be reachable).

## 1. What we need from Windows

| Item | Why | Where it comes from |
|------|-----|---------------------|
| **SCC camera enable register values** (`Power0` @0x210, `Power1` @0x220, `PowerEn`/`Mclk` @0x240, `Enable` @0x1e0, `Reset` @0x1d0) | The exact 32-bit values the SCC writes to bring the camera online (input power to the PMIC). | Live SCC register block at `0x14001b000` (Windbg `!dc`/`dd`, or `rdmsr`/MMIO dump). |
| **`C0P#/C0G#` pin map** (`C0P0`..`C0P3`, `C0G0`..`C0G3`) | CRD PMIC GPIO → rail mapping (which pin enables DOVDD / DVDD / AVDD / Mclk). Used to build a correct `_CRS`/`_DSM` so the Linux driver wires the right pins. | SCC register `DEVICE_CONTEXT` @0x270, or the `SkcController.sys` register table. |
| **CRD adoption sequence** (`CL00`, `C0TP`, `C0GP`, `C0CV`, `C0W0`..) | The ordered writes that set `CL00 && C0TP==1` (makes PMIC `_STA=0x0F`) and `C0GP=N` (exposes GPIOs). | `SkcController.sys` init routine, or a live register timeline. |
| **Mclk enable bit** in `PowerEn`/`Mclk` @0x240 | Which bit turns the Mclk on, and at what frequency (should be 19.2 or 24 MHz). | SCC register dump. |
| **`SCSS`** (CAM0 `_STA` gate) | Confirms the SCC global that gates the sensor's `_STA`. | `SkcController.sys` / register dump. |

## 2. How to get it (pick one)

### A. Live Windows, read SCC registers (most direct)
Boot the Windows side of this dual-boot and, as admin, dump the SCC register
block. Options:
- **Windbg** (kernel debugger attached or `kd`): `!dd 14001b000 L40` (or the
  SCC's BAR base — see §3) to read `0x14001b1d0..0x14001b270`.
- **A small usermode tool** that MMIO-maps the SCC PCI BAR and reads the offsets
  above. The BAR base is the one unknown (see §3).
- **PowerShell + a driver**: `SkcController.sys` already maps these registers;
  a tiny kernel-mode helper or even a Sysinternals `RAMMap`-style dump can read
  them.

Capture: `Power0`(0x210), `Power1`(0x220), `Enable`(0x1e0), `Reset`(0x1d0),
`PowerEn/Mclk`(0x240), `DEVICE_CONTEXT`(0x270). Also record the values *while the
camera is streaming* (so Mclk + all enable bits are set).

### B. Static, from `SkcController.sys` (no boot needed)
Pull `SkcController.sys` from the Windows install (`C:\Windows\System32\Drivers\`)
and reverse the register table:
- Strings/consts around `0x14001b` reveal the register offsets.
- The init routine contains the adoption sequence (`CL00`/`C0TP`/`C0GP`) and the
  `C0P#/C0G#` pin table.
- IDA/Ghidra (`ghidra` tool available here) can decompile the register-handling
  function; I can run Ghidra on the `.sys` if you hand it over.

## 3. The one unknown: SCC PCI BAR base
The register block lives at `0x14001b????`. The `????` is a BAR-mapped base I
couldn't resolve from Linux. Get it from Windows:
- `pnputil` / Device Manager → SCC device → Resources → Memory base.
- Or Windbg: `!pcidump` / `!devtree` → find the "Intel SCC"/Super IO device and
  its memory resource.
That base + the offsets above = the full SCC register map.

## 4. What I do with the data
1. Complete the CRD-visibility patch (`int3472-discrete` CRD `_DSM`/`_CRS` parser +
   patched DSDT that forces `CL00/C0TP`, sets `C0GP=N`, wires `C0P#/C0G#`) so the
   Linux driver binds the PMIC and exposes DOVDD/DVDD/AVDD/Mclk.
2. If the register block turns out to be MMIO-reachable, reproduce the SCC enable
   writes to power the camera. If not, the data still lets me build the correct
   CRD `_CRS`/`_DSM` + confirm whether the Mclk is SCC-gated or available once the
   PMIC is adopted.
