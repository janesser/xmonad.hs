Forged idea — Chuwi UBook XPro keybindings on Arch

2026-10-23 · session: pi (bmad-forge-idea, in-conversation — no BMad core installed, no memlog) · machine: flowerpower (UBook XPro, Hyprland/Omarchy)

Outcome: Hardened. The idea — "tweak keybindings for the Chuwi UBook XPro keyboard on Arch, replacing a stale Debian-era xkb fork" — survived scrutiny and left the session as a 27-line, system-wide, upstream-tracking xkb variant, implemented and verified. Not merely clarified.

The idea, examined

The Chuwi keyboard cover is a 104-key board: no key emits the scancode of <LSGT> (KEY_102ND, 86) — confirmed by evtest (key left of 1 = KEY_GRAVE, key left of left-Shift = KEY_BACKSLASH). The stock German layout binds | (bar), < (less), > (greater) only to that missing key, so on this hardware all three characters were unreachable. The user's original file was a 1261-line full fork of de, frozen at the pre-2023-08 DIN revision, deployed to package-owned /usr/share/X11/xkb — and not actually deployed on this machine at all.

Locked decisions

DecisionWhatWhy (pressure tested)
Shape Variant de(chuwi_ubook_xpro) via a local file named de defining only that group Empirically proven: libxkbcommon falls through to the next include path per (file, group) — de(basic), de(e1), … keep resolving to the package; include "de(basic)" inside the local file resolves to the package file, not itself. No fork, tracks upstream.
Placement /etc/xkb/symbols/de System-level (any user) was a requirement. /etc/xkb is searched before the packaged xkeyboard-config. ~/.config/xkb rejected (per-user only); /usr rejected (package-owned).
Binding AltGr+y = |, AltGr+Shift+y = <, AltGr+Shift+x = > The user's April 2025 settlement, re-confirmed with eyes open: it costs » (was AltGr+y) and ›‹ (upstream's 2023-08 level-4) — a conscious trade for the characters actually typed. Git history of the file showed three prior design iterations; this is the settled one.
Activation sudo localectl set-x11-keymap de pc105 chuwi_ubook_xpro --no-convert /etc/vconsole.conf is owned by systemd-localed — edit it through its owner, not sed. --no-convert keeps the console KEYMAP=de. localectl compiles the keymap before writing — order (file first) is enforced and it doubles as the end-to-end check.
Deployment Change-hash-gated run_onchange script (repo convention, auto-poweroff pattern); old 1261-line fork git rm'd Re-runs only when the input changes; idempotent. The fork was the disease: stale since 2020-11, re-merging upstream by hand. Commit ed649d6.

Rejected, and why

  • Full fork of de under a new layout name (the status quo) — stale, 1261 lines, package-owned target dir. Killed.
  • Standalone layout de.chuwi_ubook_xpro — dot-named files are standalone layouts, proven; worked, but costs a layout-name change in vconsole and in the bar widget. Superseded by the variant (lighter, per user requirement).
  • Shadowing de with a full copy — initially believed necessary; the per-group fall-through test killed it. Would have been the 1261-line disease in new clothing.
  • xkb options file (chuwi:pipe) — the only true "extension" besides the variant, but no XKBOPTIONS carrier in vconsole.conf and Omarchy hard-codes kb_options; can't be turned on system-wide.
  • Hyprland bind / udev hwdb / compose sequence — wrong layer for a character everyone needs (TUIs, login manager, fcitx5 passthrough), or too deep for frequent use.
  • Editing vconsole.conf by hand (sed) — file is labeled systemd-owned; localectl validates by compiling, manual editing does not.

Weak points that survived scrutiny

  • localectl list-x11-keymap-variants de does not list local /etc/xkb variants (registry listing quirk) — cosmetic, compiler path is proven.
  • The repo's dot_bashrc is stale (pre-Omarchy) — every cz apply prompts; answer N or re-add the live file when convenient. Unrelated, pre-existing.
  • If any other machine still has the old /usr/share/X11/xkb/symbols/de.chuwi_ubook_xpro deployed (pre-usr/-ignore), remove it by hand — chezmoi no longer ships or removes it.
  • tty console keymap still has no | (out of scope by design).
  • The »/›‹ loss is real: if German typography usage grows, the slot for » (e.g. TLDE level 3/4, currently ′/″) is the natural re-placement target.
